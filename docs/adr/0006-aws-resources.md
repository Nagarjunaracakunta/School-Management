# ADR 0006: AWS resources, and what changed from the original plan

Status: Accepted
Date: 2026-10-24

This record changes decision D4 of [ADR 0001](0001-core-architecture-decisions.md) and adds the AWS-level decisions of Phase 13.

## Revising D4: no "DLQ alert" Lambda and no "overdue-fee" Lambda

D4 planned two Lambda functions. Looking at them closely, neither earns its place:

| Planned Lambda | Problem | Replacement |
|---|---|---|
| Alert when the dead-letter queue has messages | A CloudWatch alarm on the queue does exactly this, with no code, no deployment and nothing to maintain | `aws_cloudwatch_metric_alarm` in the observability module |
| Daily overdue-fee reminder | It must find overdue fees. Reading the Fee database directly breaks the service's ownership of its data; calling the Fee API needs service-to-service authentication we do not have | A Kubernetes CronJob running the **Fee service image** (Phase 15). It uses the Fee service's own database role and its own outbox, so no boundary is crossed |

A Lambda IS the right tool for one job, and it fills a gap flagged in Phase 8: SNS cannot email arbitrary addresses.

| New Lambda | Job |
|---|---|
| `notification-delivery` | Subscribed to the notifications topic. For `channel=EMAIL` it calls Amazon SES; for `channel=SMS` it publishes to the phone number. Failures are retried twice, then parked in a failure queue that has an alarm |

## Decisions

| # | Decision | Reason | Revisit when |
|---|---|---|---|
| D47 | **EKS Pod Identity** (not IRSA) gives pods their AWS permissions. The IAM roles trust `pods.eks.amazonaws.com` | The trust policy does not name a cluster, so roles can be created and reviewed before the cluster exists, and one role works in any cluster | We need to support clusters outside EKS |
| D48 | One IAM role per service, built from an explicit list of actions and resources. The iam module **rejects any wildcard** | Least privilege enforced by code, not by remembering to check | Never expected |
| D49 | RDS manages the administrator password itself (`manage_master_user_password`), stored and rotated in Secrets Manager | No database password is ever in Terraform state, a plan or a log | Never expected |
| D50 | Per-service database passwords are generated by an **ephemeral** resource and written through a **write-only** argument | They never enter the Terraform state either. Rotation = bump `credentials_version` | Never expected |
| D51 | The token signing key is generated outside Terraform (`scripts/aws/put-jwt-key.sh`); Terraform creates only the empty secret | A private signing key must not pass through the state file | A KMS asymmetric key signs tokens inside AWS (the key never leaves KMS) |
| D52 | The database security group starts with no rules; the EKS module opens exactly one (from the nodes) in Phase 14 | "Closed until opened" | Never expected |
| D53 | CloudFront routes single-page-app URLs with a **CloudFront Function** on the static behavior only, not with custom error responses | Custom error responses apply to the whole distribution and would turn API 404s into `index.html` with status 200 | Never expected |
| D54 | AWS-managed encryption keys everywhere for now (SQS-managed, S3 AES-256, `alias/aws/sns`, the default RDS and Secrets Manager keys) | No key policies to get wrong while learning; still encrypted at rest | A compliance rule requires customer-managed keys (CMK) |
| D55 | The alerts topic is **not** encrypted; the notifications topic is | CloudWatch alarms cannot publish to a topic using an AWS-managed key. Alert text contains no personal data; notification messages do | We add a CMK whose policy allows CloudWatch |

## Known limits

- **Email needs SES set up by a human:** the sender address must be confirmed (AWS emails a link), and a new AWS account is in the SES **sandbox**, which delivers only to verified recipients. Production access is requested in the console.
- **SMS to India needs regulatory registration (DLT)** with sender ID and templates before messages are delivered. Until then SMS works only in some regions/accounts.
- **"Sent" means "handed to SES/SNS"**, not "arrived in the inbox". Bounces and complaints need an SES configuration set feeding back into the Notification table (later).
- **WAF** is an optional input on the CloudFront module but is not created yet.
